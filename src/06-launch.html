本章要点

本地看得见不算完成，别人能打开才算完成。这一步通常只花 15 分钟，但它是「玩一玩」和「真的做了个网站」的分界线。

一、先分清：本地预览和上线是两件事

你在自己电脑上双击 index.html，浏览器打开了页面——这个地址通常是 file:///C:/... 开头。这个网址只有你能用，发给别人是打不开的。

上线（部署）做的事，就是把这些文件复制到一台一直开着的公网服务器上，然后给你一个 https:// 开头的网址。这个网址任何人都能打开。

本地预览 上线之后
地址形式file:///C:/... 或 localhosthttps://你的站点地址
别人能看吗不能能
适合干什么自己检查效果、反复修改分享、收反馈、正式使用
成本0静态站点通常也是 0

二、三种上线方式，按省事程度排

方式一：让 Agent 直接部署（最省事）

如果你用的 Agent 支持连接部署平台，直接说一句「把这个站点部署上线，返回访问地址」，它会完成上传和发布。你只需要点一下确认、拿到链接。

适合：新手第一次上线、只需要一个能分享的链接。

方式二：拖拽上传到静态托管平台

把整个文件夹拖进平台的上传区，几十秒后得到网址。多数平台提供免费额度和自动 HTTPS，超出后按量付费。常见选择是各家云厂商的静态网站托管、以及面向开发者的静态托管服务。

适合：完全不想接触命令行、又希望有稳定长期地址的人。

方式三：代码仓库 + 自动构建（最「正统」）

把项目推到代码托管平台，开启 Pages 功能，之后每次更新代码就自动重新发布。首次配置需要几步，但后续改版最省心。

适合：会持续维护、或者以后要交给别人接手的情况。

对新手来说，先用方式一拿到第一个链接，建立「我真的做出了一个网站」的实感，比一开始就研究配置重要得多。

三、上线的具体动作

检查入口文件

确认首页文件名是 index.html（小写）。这是服务器默认打开的文件，命名不对会出现「目录列表」或 404。

向 Agent 确认
检查这个项目准备上线还缺什么：
1. 首页文件是否叫 index.html 且拼写正确；
2. 所有资源引用是否都是相对路径（不要出现 C:/Users/... 这种本地绝对路径）；
3. 有没有引用本地才有的文件（比如桌面上的图片）；
4. 把需要修的地方直接改掉。

第 2 条是新手上线最常见的翻车点：图片用的是本地绝对路径，部署后图片全变成破图。

执行部署，拿到网址

按你选的方式操作。用 Agent 部署时，它一般会返回一个可访问地址。

用三种设备验证

  • 电脑浏览器打开——看整体布局；
  • 手机打开——看有没有横向滚动、字会不会太小；
  • 把链接发给一个朋友，问一句：「你能打开吗？」

第三步听起来多余，但它能排掉「只有你自己能打开」这一类问题。

补上分享信息（让别人愿意点）

链接发到聊天软件里时会显示一个标题和一句描述，这就是 SEO 基础里的 meta 标签在起作用。让 Agent 补上：

补 meta 信息
补全分享相关的 meta 标签：
1. <title> 写成年份会变的话术：「周末手冲咖啡课 · 一个下午学会」
2. <meta name="description"> 一句话讲清是什么、适合谁、怎么报名；
3. 补 og:title / og:description / og:image / og:url，便于分享时预览；
4. 一句 <html lang="zh-CN"> 确认语言标注正确。

关于域名：先别急着买

平台给的网址（一串字母）完全够用。等你确认这个网站会长期存在、并且真的有人访问，再去买一个属于自己的域名，指向这个站点。先买域名、后想内容，是最典型的顺序颠倒。

四、怎么收集反馈才有用

把链接发出去，然后不要问「你觉得怎么样」。这种问题只会得到「挺好的」。换成具体问题：

别这么问 这么问
好不好看？打开之后，你第一眼看懂这个页面是干什么的吗？
有什么建议？哪一句话你没看懂？
完整吗？如果想报名，你知道该点哪里吗？
——你猜价格大概是多少？（验价格是否够醒目）

「第一眼看懂吗」「知道点哪里吗」这两个问题的答案，比一百句「挺好看」都有价值。

五、迭代循环：把反馈变成可执行的修改

收到的反馈往往是模糊的（「有点空」「不够吸引人」）。你的工作是把它翻译成一句具体的修改指令：

01

收到模糊反馈

「感觉太空了，不知道要干什么。」

02

翻译成具体问题

不是空，是首屏缺一个明确的行动指引。访客看完标语不知道下一步做什么。

03

变成一句修改指令

「在首屏标语下方 32px 处加一个报名按钮，文案『查看课程时间』，并在按钮下方用 13px 灰字写上『每周六下午，还剩 6 个名额』。」

04

改完重新发布，再问一遍

同一个访客再看一次：「现在知道点哪里了吗？」——这就是完整的迭代闭环。

别怕改坏

在动手改之前，让 Agent 先复制一份当前版本（比如 index-v1.html），或者把项目整理成一个代码仓库。有了退路，你才敢大胆试。

六、让页面打开更快（新手版，三件事）

  • 图片压缩：上传前把图片压到 200KB 以内。手机拍的原图动辄 5MB，是页面变慢的头号原因。
  • 图片懒加载：非首屏图片加 loading="lazy"，让浏览器先加载看得见的部分。
  • 别引外部大字体：中文字体文件通常几 MB，用系统字体栈就够，视觉上也没有损失。

网站已经上线了。最后一章，我们把上线前该检查的内容和最常见的坑一次说清——它也可以当作以后每次发版的固定流程。
