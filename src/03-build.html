Step By Step

三步，做出一个网站

每步分两栏：左边你做的，右边 Agent 做的。照着走一遍。

STEP 1 把提示词给 Agent，让它生成
你要做的

打开对话窗口，把第 2 章的四句话模板（或下方示例）发给它。

Agent 做的

拆解需求，一轮生成完整的 HTML + CSS 代码。

STEP 2 如何让 Agent 修改
你要做的

把不满意的点用一句话说清（能截图更好），一次只说一件事。收到新代码后，覆盖保存成 index.html，刷新浏览器看效果。

Agent 做的

只改你指的地方，回给你完整的新代码；需求含糊时它会反问你。

⚠️ 最常见的坑：文件名后缀必须是 .html。Windows 默认隐藏扩展名，小心存成了「index.html.txt」。
STEP 3 上线五步，做完一步勾一步
✓ 在 github.com 注册账号（如果还没有）。
✓ 右上角「+」→「New repository」，名字随便起，Public，不勾任何初始化。
✓ 按提示在本地 my-site 文件夹里运行三条 git 命令（页面自带复制按钮）。
✓ 回到仓库 → Settings → 左侧 Pages → Source 选 main 分支根目录 → Save。
✓ 等一分钟，页面顶部出现 https://你的用户名.github.io/仓库名/，发给任何人即可。

Example Prompt

第 1 步的示例提示词

不想自己写？直接复制这条发给 Agent，先把流程跑通。

PROMPT · 咖啡课落地页
我想要一个咖啡课程报名落地页。受众是 25–35 岁想学手冲的城市白领。风格极简黑白、大字标题、像 Apple 官网那样留白多。单页，顶部一句话主张 + 三个课程亮点 + 底部报名表单。

到这里你就掌握了核心循环：写需求 → 看效果 → 改需求。剩下的只是熟练度。

Troubleshooting

新手最常踩的四个坑

对着症状找原因，一句解法就能救你两小时。

坑 01
双击打开全是源代码
原因文件存成了 .txt（Windows 默认隐藏扩展名）
解法手动把文件名改成 index.html 再打开
坑 02
页面里的图片全打不开
原因对话型 Agent 经常编造图片地址
解法图片先存到本地，src 改成相对路径（如 images/coffee.jpg）
坑 03
改了文件但页面没变化
原因浏览器缓存；GitHub Pages 也要 1–3 分钟重新部署
解法按 Ctrl + F5 强制刷新，线上改动稍等再看
坑 04
一次提太多需求，Agent 改崩了
原因改动累计越多，Agent 越容易丢上下文
解法每次只说一件事，改完满意再提下一条
