本章要点

Agent 做网站是 七个来回，不是一句话搞定。理解这个节奏，你就不会在第一步就要它「给我一个完整的网站」——那是新手最贵的错误。

一、七个步骤的全貌

下面这条流程，无论是用建站生成型工具还是编程型 Agent，本质都一样。区别只是有些步骤被工具自动合并了。

01

澄清需求

把「我想做个网站」变成「我要做一个面向 X 人群、包含 Y 内容的 Z 风格单页」。

你负责
说清楚目的与受众，给一个参考网站
Agent 负责
追问遗漏信息，复述你的需求让你确认
02

定义信息结构

确定页面从上到下有哪些区块，以及它们的先后顺序。这一步不涉及任何视觉，只谈「讲什么」。

你负责
确认区块顺序，删掉不需要的
Agent 负责
给出区块清单与每块的内容要点
03

定下设计基调

从参考站或设计系统里提炼出：主色、字体气质、圆角大小、疏密程度。这一步定了，后面不会来回漂。

你负责
给出 1–2 个参考网站，说明喜欢它哪里
Agent 负责
输出具体的色值与字体方案
04

生成页面骨架

先只写结构：有哪些区块、每块放什么内容、标题层级是什么。此时页面是「没有装修的毛坯房」。

你负责
看结构是否讲清了你想讲的事
Agent 负责
写出语义化的 HTML 结构
05

套用样式

把第 03 步定下的设计基调落到 CSS 上：颜色、字号阶、间距、圆角、悬停反馈。

你负责
看效果、指出「太挤 / 太花 / 不够稳重」
Agent 负责
写样式并保证全站统一
06

响应式与细节

手机宽度下不溢出、不断行错乱；补上悬停态、加载态、空状态这些「小事」——它们决定专业度。

你负责
在手机上真机看一眼
Agent 负责
加断点、修溢出、补交互细节
07

部署与迭代

发布到公网拿到链接，收集反馈，然后回到第 05 或 06 步继续改。网站没有「做完」，只有「这一版」。

你负责
分享出去、收集具体意见
Agent 负责
执行部署、按反馈批量修改

二、关键在节奏：为什么不能一口气要全套

新手最典型的做法是打开工具，输入一句：「帮我做一个好看的网站」，然后期待奇迹。结果通常是：页面能看，但你不知道哪里不对，也不知道怎么改。

原因是 Agent 在一次回答里同时决定了讲什么、怎么排、长什么样。三件事捆在一起，你只能笼统地评价「不好看」，而笼统的反馈无法执行。

把它拆成七步之后，每一步的验收标准都变得具体：

  • 第 02 步你只说：「第三块和第四块换位置。」
  • 第 05 步你只说：「正文行高再松一点，标题和副标题的差距拉大。」
  • 第 06 步你只说：「手机上这段文字溢出了，修一下。」

具体的小要求，Agent 一次就能改对；笼统的大要求，它能给你十个版本，你都不满意。

三、三种常见的失败模式

失败模式一：一句话要一个完整网站

结果：一次产出很大，但结构、视觉都不可控，你还得整段重写提示词重来。
改法：把要求拆开，先只要结构，满意了再要样式。

失败模式二：全程不给参考

「简约大气」这四个字，在 Agent 眼里有几十种解释。它只能猜。
改法：丢一个参考网站链接，再说「照它的留白和字重关系，但换成我们自己的内容」。

失败模式三：不验收就往下走

结构还没看就催样式，样式没看就催上线。最后问题叠在一起，无从下手。
改法：每一步都真的看一眼。看效果花 30 秒，返工花 30 分钟。

四、一个真实的时间预算

以「一个单页产品介绍站」为例，用方案 B（对话型 + 编程型 Agent）走完七步，大致是这样：

步骤 预计耗时 最容易返工的地方
01 澄清需求15–20 分钟目标没说清楚，后面全歪
02 信息结构10 分钟区块贪多，页面变成堆料
03 设计基调10 分钟给不出参考，来回试风格
04 页面骨架5 分钟——
05 套用样式20–30 分钟用「不好看」这种模糊反馈
06 响应式与细节15 分钟忘了在手机上看
07 部署与迭代15 分钟首次配置环境

合计约 1.5 至 2 小时。其中真正「动手」的时间不到一半，其余都在想清楚和看效果——这就是正常的比例。

记住这句话

Agent 让「写」变得几乎免费，所以瓶颈从「会不会写」变成了「说不说得清、看不看得出」。本教程后面两章分别训练这两种能力。
