B · 改完没变化
先按 Ctrl + F5 强制刷新，把旧缓存丢掉；还不行就等一下再看——线上部署本身也需要一点时间。
A · 存成 index.html
后缀必须是 .html；Windows 默认隐藏扩展名，小心存成了「index.html.txt」。
B · 推到 GitHub
建一个仓库，把做好的文件传上去。
C · 开启 Pages
在仓库 Settings → Pages 里开启，拿到你的网址。
上线五步，做完一步勾一步
✓ 在 github.com 注册账号（如果还没有）。
✓ 右上角「+」→「New repository」，名字随便起，Public，不勾任何初始化。
✓ 按提示在本地 my-site 文件夹里运行三条 git 命令（页面自带复制按钮）。
✓ 回到仓库 → Settings → 左侧 Pages → Source 选 main 分支根目录 → Save。
✓ 稍等片刻，页面顶部出现 https://你的用户名.github.io/仓库名/，发给任何人即可。

进度 0 / 5

部署细节与四个新手坑 除了存文件、推仓库、开 Pages，最容易卡住的地方都在这儿。

到这里你就掌握了核心循环：写需求 → 看效果 → 改需求。剩下的只是熟练度。

Troubleshooting

新手最常踩的四个坑

对着症状找原因，一句解法就能救你两小时。

坑 01
双击打开全是源代码
原因文件存成了 .txt（Windows 默认隐藏扩展名）
解法手动把文件名改成 index.html 再打开
坑 02
页面里的图片全打不开
原因对话型 Agent 经常编造图片地址
解法图片先存到本地，src 改成相对路径（如 images/coffee.jpg）
坑 03
改了文件但页面没变化
原因浏览器缓存；GitHub Pages 重新部署也需要等一会儿
解法按 Ctrl + F5 强制刷新，线上改动稍等再看
坑 04
一次提太多需求，Agent 改崩了
原因改动累计越多，Agent 越容易丢上下文
解法每次只说一件事，改完满意再提下一条
